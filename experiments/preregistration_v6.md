# Pre-registration: v6 canonical-set expansion (script 24)

**Status:** FROZEN. Written before any v6 extraction or analysis runs.

**Purpose:** test the *default-to-rarest-canonical* mechanism identified in §3.7.14 / §3.7.15 by expanding the canonical set in a way that disentangles two confounded explanatory dimensions:

- **Token frequency in training data** — multi-subword rare canonicals (`xor`, `nand`, `negate`) won in v5 partly because they are formal-logic / programming terms with near-zero frequency in natural-English training corpora.
- **Subword-tokenization shape** — the same canonicals are also all 2-3 subword pieces, which matches the subword shape of all 16 invented words (uniformly 2-3 pieces) more closely than the single-subword high-frequency canonicals.

These are confounded in the current v5 data (every winning canonical is both rare *and* multi-subword; every losing new canonical is both common *and* single-subword). The v6 expansion adds canonicals that span the {frequency × subword-count} cross-tab so that the two dimensions can be separated empirically.

This pre-registration is also the response to the reviewer's garden-of-forking-paths concern (the M2-arity introduction, the lucky-default detector refinement, and the v3→v4→v5 multi-scope analysis were all developed post-hoc on the same data). The full final analysis battery is specified below before any v6 cache is extracted; deviations from this spec at analysis time must be reported as exploratory and flagged in the writeup.

---

## 1. Canonical set (v6)

| Canonical | Arity | Subword cells (target) | English freq (target) | Role |
|---|---|---|---|---|
| `and` | B | 1pc | high | v3/v4/v5 carryover |
| `or` | B | 1pc | high | v3/v4/v5 carryover |
| `implies` | B | 1pc | mid | v3/v4/v5 carryover |

| `nand` | B | 2pc (varies by tokenizer) | very low | v5 carryover; multi-pc / LF |
| **`nor` (new)** | B | **1pc** | **low** | **single-pc / LF — frequency-driven prediction: ATTRACTS** |
| **`iff` (new)** | B | **2-3pc** | **very low** | **multi-pc / LF — control for v5 attractors** |
| **`unless` (new)** | B | **1pc** | **mid** | **single-pc / MF — should NOT attract on either reading** |
| `not` | U | 1pc | high | v3/v4/v5 carryover |
| `necessarily` | U | 1pc | mid | v3/v4/v5 carryover |

**v6 chance baseline**: 1/15 = 0.067 for 15-class M2-canonical; 0.50 for the coarsened binary-vs-unary M2-arity (the binary/unary split is 8/7 ≈ 53%/47%, so the actual chance baseline for M2-arity is 0.53).

**Audit gate**: at v6 cache extraction time, script 24 prints the tokenization for all 15 canonicals across all three model tokenizers. If any new canonical fails its target profile (e.g., `nor` tokenizes as 2-pc instead of 1-pc in any model, or `unprovably` tokenizes as 1-pc), that canonical is reported but flagged "OUT-OF-DESIGN" in §3.7.16 and excluded from the disentanglement analysis. The remaining canonicals carry the falsification predictions.

## 4. Templates

**Carryover templates** (v6_carryover): same as scripts 22d/23 — used for primary M1/M2/M3/M4 measurements at v6.

**Held-out templates (v6_heldout)**: a syntactically-distinct template set, generated by the same `make_*_prompts` constructor used by scripts 22d/23 but with disjoint lexical scaffolding (the `template_id` set in `experiments/stimuli/templates_heldout.py`, generated by the same `seed=17` blake2b protocol as scripts 22d/23 v2 stable seeds). The held-out set is used **only** for M1 within-condition CV validation — the result we report is: does the v6 within-condition probe accuracy at the focus layers reach the same plateau on held-out templates as on the carryover templates? If not, the within-condition arity-region attractor finding from Phase 0/1 is template-leakage-contaminated.

The held-out template set is **not** used for M2 / M3 / M4 — those use the carryover templates only, for direct comparability with v5.

## 5. Metrics (frozen definitions; same as scripts 22d/23)

| Metric | Definition | Threshold |
|---|---|---|
| **M1tr** | Within-condition probe 5-fold CV accuracy on training canonicals | report only |
| **M1te** | Within-condition probe accuracy on held-out canonicals (different invented words, same template family) | ≥ 0.65 = structural |
| **M1heldout (new for v6)** | M1tr accuracy when probe is trained on v6_carryover and evaluated on v6_heldout templates | ≥ 0.65 = template-leakage-clean |
| **M2-canonical** | Cross-notation 15-class accuracy on canonical operators | ≥ 0.65 = PASS, ≥ 0.30 = AMBIG, else FAIL |
| **M2-arity** | Same probe, coarsened to binary-vs-unary | ≥ 0.65 = PASS |
| **M4a** | Invented unary mass (% invented predicted to a unary canonical) | report only |
| **M4b** | Intended-arity agreement: % invented words whose top-canonical matches intended arity | ≥ 0.65 = PASS-arity |
| **M4c** | Canonical catchment concentration: max fraction of invented mass on any single canonical | ≤ 0.85 = distributed |
| **pwmin** | min over invented words of (within-word top-canonical concentration) | ≥ 0.95 = LUCKY-DEFAULT flag |

**Lucky-default detector**: a cell with M4b ≥ 0.65 but `pwmin ≥ 0.95` is reported with the `LUCKY-NEG *L` verdict, indicating the per-word predictions are too concentrated to be arity-respecting in the sense the M4b metric was meant to capture. This refinement was introduced in §3.7.11 (post-hoc) and is now pre-registered for v6.

**Cell verdicts**:

- **PASS-arity**: M2-arity ≥ 0.65 AND M4b ≥ 0.65 AND M4c ≤ 0.85 AND pwmin < 0.95 AND M4a ∈ [0.20, 0.80].
- **M2A-ONLY**: M2-arity ≥ 0.65 AND not PASS-arity.
- **LUCKY-NEG**: M4b ≥ 0.65 BUT pwmin ≥ 0.95.
- **FAIL**: all other.

## 7. Pre-registered falsification predictions

The default-to-rarest-canonical mechanism (§3.7.14 / §3.7.15) makes three competing predictions about which canonicals win the v6 invented-mass aggregate distribution. Each prediction has a quantitative threshold; the v6 outcome will distinguish them.

### P_FREQ (frequency-driven attraction)

If invented mass is routed primarily by training-corpus frequency, the new low-frequency single-subword canonicals should attract substantial mass:

- **P_FREQ.1**: `nor` (1pc, LF) ≥ 10% of v6 invented mass aggregated across all v6 cells, *per model*. (At v5 chance for a single canonical: 1/15 ≈ 6.7%.)
- **P_FREQ.2**: `iff` ≥ 10% of v6 mass per model.
- **P_FREQ.3**: `unprovably` ≥ 10% of v6 mass per model.
- **P_FREQ.4**: `unless` ≤ 5% of v6 mass per model (MF binary control; should not attract).
- **P_FREQ.5**: `definitely` ≤ 5% of v6 mass per model (MF unary control; should not attract).
- **P_FREQ.6**: aggregate {nor + iff + unprovably} ≥ 35% of v6 mass per model.

### P_SUBWORD (multi-subword-shape attraction)

If invented mass is routed primarily by subword-tokenization shape (multi-piece canonicals match the multi-piece invented words), the new multi-piece canonicals should attract while the new single-piece canonicals should not, regardless of frequency:

- **P_SUBWORD.1**: `iff` ≥ 15% of v6 mass per model (multi-piece, LF).
- **P_SUBWORD.2**: `unprovably` ≥ 15% of v6 mass per model (multi-piece, LF).
- **P_SUBWORD.3**: `nor` ≤ 5% of v6 mass per model (single-piece, LF — frequency-driven would predict attraction; subword-driven predicts no attraction).
- **P_SUBWORD.4**: aggregate {all multi-piece canonicals: xor, nand, negate, iff, unprovably} ≥ 70% of v6 mass per model.
- **P_SUBWORD.5**: aggregate {all single-piece canonicals: and, or, implies, not, necessarily, possibly, always, nor, unless, definitely} ≤ 30% of v6 mass per model.

### P_INTERACTION (both)

If both dimensions matter, the multi-piece LF canonicals will dominate but the single-piece LF canonicals will pick up moderate mass:

- **P_INT.1**: aggregate {iff + unprovably + xor + nand + negate} > aggregate {nor + and-via-default-cell + unless + definitely + possibly + always}.
- **P_INT.2**: `nor` attracts in [5%, 15%] range (moderate; falsifies pure P_SUBWORD but does not reach P_FREQ).
- **P_INT.3**: `unless` and `definitely` ≤ 5% each (controls hold).

### Adjudication

After v6 extraction + sweep, the §3.7.16 writeup will classify the outcome:

- **P_FREQ supported, P_SUBWORD falsified** if P_FREQ.1, .2, .3, .6 hold AND P_SUBWORD.3 fails.
- **P_SUBWORD supported, P_FREQ falsified** if P_SUBWORD.4, .5 hold AND P_FREQ.1 fails (`nor` ≤ 5%).
- **P_INTERACTION supported** if P_INT.1, .2, .3 all hold.
- **None supported** if `unless` or `definitely` attracts ≥ 10% (any model), or if the control canonicals destabilize.
- **Out-of-design** if the v6 tokenization audit reveals more than 2 of the 5 new canonicals fail their target profiles.

## 8. PASS-arity falsification predictions

The §3.7.14 finding is that *all* v3-PASS-arity cells retract at v5 canonical-set expansion. The v6 expansion gives a further falsification opportunity:

- **P_RETRACT**: zero PASS-arity cells in any model at v6 scope. (Consistent with the operator-set-bound interpretation; novel-operator generalization fails uniformly.)
- **P_SURVIVE**: if any model has ≥ 1 PASS-arity cell at v6, the operator-set-bound finding is partially retracted in that model and the writeup must report it.

This is the cleanest in-data falsifier for the operator-set-bound headline.
